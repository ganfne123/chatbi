一、锚表选择：先理解用户在问什么
1.1 为什么"事实表优先"不够
在星型模型中，SQL 的惯用写法是 FROM 事实表 JOIN 维度表，所以很多实现会简单粗暴地
优先选事实表。
但这只在问题是指标型时成立。如果问题是实体型，把事实表当主表会过滤掉没有事实记录的
实体。

问题：列出所有客户
sql
-- 错误写法
FROM sales_orders
JOIN dim_customers ON sales_orders.customer_id =
dim_customers.customer_id
这种写法只返回下过订单的客户；没有订单的客户被 INNER JOIN 过滤掉了，与"列出所有客
户"的语义不符。

问题：哪些客户没有下过订单

sql
-- 错误写法
FROM sales_orders
JOIN dim_customers ON sales_orders.customer_id =
dim_customers.customer_id
这种写法永远找不到"没有订单的客户"。正确写法应该以 dim_customers 为主表，再用
LEFT JOIN 关联订单：
sql
FROM dim_customers
LEFT JOIN sales_orders ON dim_customers.customer_id =
sales_orders.customer_id
WHERE sales_orders.order_id IS NULL

选好锚表后，还要做一步连通性校验：如果锚表无法到达某个目标表，说明这组表本身不应该
被 Join 在一起。
最典型的例子是 sales_orders 和 finance_expenses：两张都是事实表，业务上独立，无法
连通。此时正确的处理不是硬连，而是提示"这些表需要独立查询"。

二、表关联图构建
2.1 概念模型
确定锚表之后，剩下的问题是：从锚表出发，如何把其他目标表连进来？
把数据库的表间关系看作一张有向图：

1. 节点 = 表

1. 边 = Join 关系，包含 Join 条件
1. 边的方向 = 从一个表指向另一个表
1. 边的属性 = 外键列、主键列、Join 类型

注意：Join 类型与方向有关。
1. 从事实表到维度表用 JOIN：每条事实记录都有对应的维度值
1. 从维度表到事实表用 LEFT JOIN：不是所有维度值都有事实记录
这种方向性直接影响"哪些客户没有订单"这类存在性查询的正确性。

三、BFS 最短路径 Join 推导
3.1 算法概述
已知锚表和目标表集合后，Join 推导分三步：
1. 选锚表：根据查询意图确定 FROM 子句主表
1. 找路径：从锚表出发，用 BFS 找到达每个目标表的最短路径
1. 合并去重：将所有路径合并，去除重复的 Join 边

3.2 BFS 最短路径
标准 BFS：
python
from collections import deque
def _bfs_shortest_path(start, end, relationships):
if start == end:
return [start]
queue = deque([(start, [start])])
visited = {start}
while queue:
current, path = queue.popleft()
for edge in relationships.get(current, []):

next_table = edge["target"]
if next_table in visited:
continue
new_path = path + [next_table]
if next_table == end:
return new_path
visited.add(next_table)
queue.append((next_table, new_path))
return None # 不可达
BFS 保证找到的是最短路径（经过的表最少），对应最少的 Join 数量。

3.3 合并路径生成 Join 序列
python
for target in target_tables:
if target == anchor:
continue
path = _bfs_shortest_path(anchor, target)
if path is None:
unreachable.append(target)
continue
for i in range(len(path) - 1):
from_t, to_t = path[i], path[i + 1]
edge_key = (from_t, to_t)
if edge_key in visited_edges:
continue # 去重：同一条边不重复 Join
visited_edges.add(edge_key)
join_info = get_join_info(from_t, to_t)
joins.append(join_info)

关键：visited_edges 去重机制。当多个目标表的路径共享中间节点时，不会产生
重复 Join。

python
def _build_on_clause(from_table, to_table, edge):
fk_cols = [c.strip() for c in edge["fk_col"].split(",")]
pk_cols = [c.strip() for c in edge["pk_col"].split(",")]
conditions = []
for fk, pk in zip(fk_cols, pk_cols):
conditions.append(f"{from_table}.{fk} = {to_table}.{pk}")
return " AND ".join(conditions)
