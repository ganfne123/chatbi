## join_resolver.py：实现查询意图识别模块（第 17 课）

参考《第 17 课：多表 Join 路径自动推理》PDF，在新建的 `join_resolver.py` 中实现了意图识别：

- 三类表类型：`anchor`（锚表/事实表，指标型）、`dimension`（维度表/参考表，实体型）、
  `fuzzy`（模糊字段，无法明确判断时用 query 中抽取的模糊词代替具体表类型）
- 主接口 `recognize_intent(query, classifier=None) -> IntentResult`（dataclass，有 `to_dict()`）
- `IntentClassifier.recognize()`：LLM 为主（DashScope qwen3.7-plus，temperature=0，要求输出 JSON），
  解析失败/调用异常自动降级到轻量关键词规则 `_rule_recognize()`（课程 1.3 节信号词），
  结果用 `source`（llm/rule）与 `fallback_reason` 标记
- `select_anchor(query, candidate_tables, classifier=None, intent_result=None)`：课程 1.4 策略，
  anchor→事实表池、dimension→维度表池、fuzzy→按关键词分+度数取中心表；可传入已算好的
  intent_result 复用，避免重复调用 LLM
- 附带 BFS Join 推导：`bfs_shortest_path` / `resolve_joins` / `build_on_clause`（支持复合键）
  / `build_sql_fragment`，表关系在 `TABLE_RELATIONSHIPS` 邻接表中手动配置
  （sales_orders、dim_customers、dim_products、exchange_rates、finance_expenses）

验证：真实 LLM 跑通 9 个课程示例，锚表与 Join（含 exchange_rates 复合键、finance_expenses
不可连通告警）均与课件一致；LLM 单次调用约 10s，故客户端设 `max_retries=1`、`timeout=15`。

约定：本文件用基础 Python（dataclass/re/json/typing），不引入 pydantic；表元数据集中在
`TABLE_META`，新增表需同步 `TABLE_META` 与 `TABLE_RELATIONSHIPS`。

### 修订（同日晚）：按用户要求大幅精简

用户反馈"单纯做意图识别不需要这么多代码"，已删除超出需求的部分：
`select_anchor` / `bfs_shortest_path` / `resolve_joins` / `build_on_clause` /
`build_sql_fragment` / `TABLE_META` / `TABLE_RELATIONSHIPS` / `score_tables_by_keywords`，
文件从约 700 行降到 247 行。现在只剩：常量与别名表、`SYSTEM_PROMPT`、`IntentResult`、
`IntentClassifier`、`_rule_recognize`、`_extract_fuzzy_fields`、`recognize_intent`。
BFS Join 推导如需可另行建文件（如 join_path.py）。

（哪怕同文件名暗示了后续章节内容）。
